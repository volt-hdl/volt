# Volt 0.1.5

Volt 0.1.5 fixes a bug of 0.1.4 that gave a wrong result without a
diagnostic: the SystemVerilog generator computed the width of `Trit`
arithmetic (`-t` and a product with a `Trit`) as if a `Trit` were a
two-bit integer ([#463](https://github.com/volt-hdl/volt/issues/463)). An untyped `let` that held such a
product could be cut to a few bits, the negation of a product lost its
top bit, a comparison of a product with a literal was rejected with
`E2005`, and `-t` in a `let` stopped `volt test` with a Verilator
warning. The generator now reads these widths from the type checker.

Upgrading is recommended for every design that uses `Trit`. A design
without `Trit` arithmetic gives the same SystemVerilog as with 0.1.4.
Read [Behavior changes](#behavior-changes) before upgrading.

## Behavior changes

Upgrading from 0.1.4: for each item below, the same input gives a
different result in 0.1.5. Each item says what 0.1.4 did, what 0.1.5
does, who is affected and what to do. All four come from one fix, the
width of `Trit` arithmetic in the generated SystemVerilog
([#463](https://github.com/volt-hdl/volt/issues/463)): the generator now
takes it from the type checker instead of computing it again. Where
0.1.4 wrote a different value or reported an error, the 0.1.4 result
went against the language specification. No new diagnostic code,
command-line option or JSON field comes with this release.

In the examples, `t` and `u` are `Trit` values, and `x`, `y`, `w` are
signed integers (`iN`).

- **A `Trit` product or `-t` in an untyped `let` has the width of its
  type** ([#463](https://github.com/volt-hdl/volt/issues/463)). 0.1.4
  counted a `Trit` as a two-bit integer when it chose the width of an
  untyped `let`: `let s = t * x * u` with `x : i14` was declared
  `wire signed [3:0]`, and the value was cut to four bits without a
  diagnostic; `let n = -t` was a three-bit wire, and comparing `n` with a
  `Trit` made Verilator report a `WIDTH` warning, which stopped
  `volt test`. 0.1.5 gives each `let` the type the specification gives
  the expression: `let s = t * x` is an `iN` (`i14` above), and
  `let p = t * u` and `let n = -t` are a `Trit` (two bits). This holds
  for a module-level `let` and for a `let` inside an `on` or `comb`
  block.
  *Who is affected:* designs that keep a `Trit` product or `-t` in a
  `let` without a type.
  *What to do:* upgrade. The value is now the one the source says.

- **The negation of a `Trit` product is one bit wider**
  ([#463](https://github.com/volt-hdl/volt/issues/463)). `-(t * x)` with
  `x : iN` is an `i(N+1)`, like the negation of any `iN`. 0.1.4 computed
  it in `N` bits: with `y : i17`, `(-(t * y))[17:1]` gave `0x0FFFF`
  instead of `0x1FFFF` for t = +1 and y = 1. The value changes where the
  width shows: in an untyped `let` and in a bit or part select. A `Trit`
  declared inside an `on` or `comb` block (`let t : Trit = ...`, or an
  untyped `let` whose value is a `Trit`) is now treated as a `Trit`: a
  product with it is generated as a selection, as for any other `Trit`,
  and follows the same width rule. In 0.1.4,
  `comb { let t : Trit = ...  let s = -(t * x) }` with `x : i8` gave `s`
  8 bits instead of 9.
  *Who is affected:* designs that negate a `Trit` product.
  *What to do:* upgrade.

- **Comparing a `Trit` product or `-t` with a literal compiles**
  ([#463](https://github.com/volt-hdl/volt/issues/463)). `t * x == 1`,
  `-t * u < 0` and, with literal factors,
  `-(t * 1 * u) * -(1 * v * w) == 1` are valid designs; 0.1.4 rejected
  them with `error[E2005]: cannot determine the width of the literal`.
  0.1.5 compiles them: a literal factor of a `Trit` product takes the
  `Trit` type (`t * 1` is a `Trit`), and a literal compared with a value
  takes the type of that value. When the type checker gives a `Trit`
  operation no width, the generator does not guess one: it reports
  `E2005` with "cannot determine the width of this Trit operation". The
  `volt` command always runs the type checker before the generator, so its users do not
  see that message.
  *Who is affected:* designs that compare a `Trit` product or `-t` with a
  literal, and so could not be compiled with 0.1.4.
  *What to do:* nothing. A workaround you wrote for 0.1.4, such as a
  typed `let` for the product, can stay or go.

- **A `Trit` times `iN` product wraps in `iN` when it is the operand of
  another operation** ([#463](https://github.com/volt-hdl/volt/issues/463)).
  The type of `t * x` (and `x * t`) with `x : iN` is `iN`. As the operand
  of another operation (`as`, an operand of `+` or `-`, a bitwise
  operation, a comparison, a select) the product is computed in `N` bits
  and wraps in two's complement: for t = -1 and x = iN::MIN
  (-2^(N-1)) the result is iN::MIN. 0.1.4 did so for every `N` except
  `N = 2`, where the `Trit` and the `i2` have the same width: there it
  computed the product in the width of the surrounding operation and gave
  +2. With `x : i2 = -2` and t = -1, `(t * x) as i12` and
  `if s { t * x } else { 0 }` written to an `i12` gave +2 in 0.1.4 and
  give -2 (`0xFFE`) in 0.1.5; `x * t & -1`, `z - (t * u) * x` and
  `((t * x | 1) as i55)[41:7]` change too. A product written directly to
  a wider target does not change: `let acc : i16 = t * w` is computed at
  the width of the target, so t = -1 and `w : i8 = -128` give +128.
  *Who is affected:* designs that use the product of a `Trit` and an
  `i2` as the operand of another operation, where the `Trit` can be -1
  and the `i2` can be -2.
  *What to do:* upgrade; the value is now the one the rule gives. A
  design that wants the mathematical result widens the `iN` side before
  the product: `t * (x as i(N+1))`. Widening after the product,
  `(t * x) as i(N+1)`, gives the wrapped value. For `x : i8 = -128` and
  t = -1, `t * (x as i9)` is +128 and `(t * x) as i9` is -128.

## Fixed

- The width of `Trit` arithmetic in the generated SystemVerilog
  ([#463](https://github.com/volt-hdl/volt/issues/463)). The input, the old result and the new one are under
  [Behavior changes](#behavior-changes).

## Other changes

These change how the project tests Volt, not what Volt does:

- The differential test, which compares the generated SystemVerilog in
  Verilator with a reference model of the specification, now generates
  `Trit` values and arithmetic, reports which types and operations it
  generated, and checks that operations the language does not define are
  rejected with the expected error. It found [#463](https://github.com/volt-hdl/volt/issues/463).
- The fuzzer now fails when it did not actually fuzz: before, the nightly
  run spent most of its time replaying its corpus, and the pull request
  run fuzzed for 0 seconds while it passed ([#305](https://github.com/volt-hdl/volt/issues/305)).

## Known issues

These bugs are open. Each one is planned for a later release; where a
workaround exists, it is given. "Suspected" marks a bug found by reading
the code and not yet reproduced by running it.

### Wrong results without a diagnostic

- **A `const` that does not fit its type**
  ([#214](https://github.com/volt-hdl/volt/issues/214)): with
  `const A : u8 = 255` and `const B : u8 = A + 1`, compile time sees 256
  and the hardware sees 0. Make every computed constant fit its type.
- **A `sync()` source clock lost in the constraints**
  ([#372](https://github.com/volt-hdl/volt/issues/372),
  [#421](https://github.com/volt-hdl/volt/issues/421)): when the source
  is an instance output, is reached through more than 8 `let`s, or is
  annotated with a clock port name (`@a_clk`) instead of a domain, the XDC
  writes `set_false_path` instead of `set_max_delay -datapath_only`
  (comment `# sync '…': ? -> …`), and with `@a_clk` a port source gets no
  capture register. Annotate with the domain name (`@A`), and check the
  `# sync` comments of the constraint files for a `?`.
- **A `create_clock` for the clock of a `clock = none` domain**
  (suspected, [#435](https://github.com/volt-hdl/volt/issues/435)). Check
  the SDC of designs with such a domain.
- **The clock outputs of an `extern module` have no domain**
  ([#208](https://github.com/volt-hdl/volt/issues/208)): nothing clocked
  by a PLL output is checked. Synchronize every value between these
  clocks by hand.
- **A register's reset value can be a signal and is not checked**
  ([#209](https://github.com/volt-hdl/volt/issues/209)). Use a constant
  reset value.
- **`E5010` is missed in a `comb` block**
  ([#217](https://github.com/volt-hdl/volt/issues/217)). Write such a
  choice as a `let`.
- **A timing constraint can apply to a second register**
  ([#219](https://github.com/volt-hdl/volt/issues/219)): `get_cells {slow_reg*}`
  also matches a register named `slow_reg`. Do not name a register
  `<name>_reg…` next to a constrained `<name>`.
- **`@false_path` and `@multicycle` are written without a check**
  ([#226](https://github.com/volt-hdl/volt/issues/226),
  [#231](https://github.com/volt-hdl/volt/issues/231)), and on a struct
  port they constrain nothing
  ([#229](https://github.com/volt-hdl/volt/issues/229)). Treat both as
  your own claim and check every path you mark.
- **Trust**: a secret passes through an unclassified input port of a
  submodule ([#210](https://github.com/volt-hdl/volt/issues/210)), and
  the trust annotation of a `wire` or `let` is not read
  ([#211](https://github.com/volt-hdl/volt/issues/211)). Annotate the
  ports.
- **Names**: a struct `let`'s flattened field can shadow a port
  ([#154](https://github.com/volt-hdl/volt/issues/154)); a module-level
  `let` can take the name of a bundle port or of `regs`
  ([#155](https://github.com/volt-hdl/volt/issues/155)); an import alias
  reaches the SystemVerilog
  ([#161](https://github.com/volt-hdl/volt/issues/161)); a test reads a
  private constant of another file
  ([#162](https://github.com/volt-hdl/volt/issues/162)); a port bound
  twice takes the last binding
  ([#229](https://github.com/volt-hdl/volt/issues/229)).
- **`@mmio`**: an unaligned base address and a repeated argument are
  accepted, and a `*/` in a `///` comment ends the C comment in the
  generated header ([#220](https://github.com/volt-hdl/volt/issues/220)).
- **A malformed `Volt.toml` is ignored**
  ([#222](https://github.com/volt-hdl/volt/issues/222)).
- **A `$finish` in an `extern` body lets the test continue**
  ([#382](https://github.com/volt-hdl/volt/issues/382)), and the test can
  pass. Write the check as a Volt contract (`invariant: a <= 100`) or an
  `assert_eq` in the test.
- **Arithmetic widths that change in 0.2.0**: an operand of `+`, `-` or
  `*` is cut before the operation, with `W2016`
  ([#266](https://github.com/volt-hdl/volt/issues/266)), and `/` or `%`
  can be computed at another width, with `W2015`
  ([#150](https://github.com/volt-hdl/volt/issues/150)). Put the
  intermediate result in a `let` of explicit width.
- **An incomplete assignment in a `comb` block infers a latch**
  ([#230](https://github.com/volt-hdl/volt/issues/230)). Assign every
  output on every path.
- **A signed shift of a wide sum can simulate wrong in Verilator 5.054**
  ([#311](https://github.com/volt-hdl/volt/issues/311), Verilator #9256):
  a signed value wider than 64 bits whose width is one more than a
  multiple of 32, computed by an expression and shifted by a port that an
  instance ties to a constant, gives `…0001` for a negative value.
- **A product with a generic `Trit` parameter is typed as an integer
  product** ([#468](https://github.com/volt-hdl/volt/issues/468)): in `module M<const S : Trit>`, `S * x` does
  not follow the `Trit` product rule above, so an untyped `let` gets a
  wider type and, as an operand, the product does not wrap in `iN`: in
  `M<1>` with `x : i2 = -2`, `(-S * x) as i12` gives +2 where
  `(t * x) as i12` with t = -1 gives -2. Copy the parameter into a `Trit`
  `let` (`let s : Trit = -S`) and multiply with that.
- **An index that is a `Trit` reads the bit of its code**
  ([#465](https://github.com/volt-hdl/volt/issues/465)): `x[t]` is accepted, and for t = -1 it reads bit 3 of
  `x` (the code `11` read as unsigned); the specification does not define
  an index of -1. Turn the `Trit` into the index you mean before indexing:
  `x[(t as i3 + 1) as u3]` reads bit 0, 1 and 2 for t = -1, 0 and +1.
- **A `Trit` in a form the generator does not recognize** (suspected,
  [#467](https://github.com/volt-hdl/volt/issues/467)) would get the width of a two-bit integer in an untyped
  `let`, the bug this release fixes. No such form is known. To rule it
  out, give such a `let` its type: `let s : i8 = t * x`.

### Errors, false warnings and failures

These do not give a wrong result: Volt stops with an error or warns where
nothing is wrong, or a step fails.

- **The one-line install failed on Ubuntu 26.04** in the project's tests,
  because of a dangling symbolic link
  ([#306](https://github.com/volt-hdl/volt/issues/306)). If it fails for
  you, use the [manual install](https://volthdl.org/tour/install.html#manual-install).
- **A false `E2003` for a reset port without a spec**
  ([#342](https://github.com/volt-hdl/volt/issues/342)): binding a reset
  port with a spec to a child's `in rst : reset` gets "expected 'reset',
  found 'reset'". Write the same spec on the child's port,
  `reset(sync, active_high)`.
- **A false `W3011`** ([#344](https://github.com/volt-hdl/volt/issues/344))
  in a module without registers that instantiates an `extern` and a Volt
  child with its own raw reset port; its label names a synchronizer that
  is not generated. The warning can be ignored there.
- **`delay<K>` inside a `fn` body has no effect** on the timing check,
  and nothing says so ([#362](https://github.com/volt-hdl/volt/issues/362)).
  Write `delay<K>` at the call site.
- **Constants written with `as`, `clog2` or `~`**
  ([#422](https://github.com/volt-hdl/volt/issues/422)): a constant written
  with `as` is checked with its uncut value (a false `W2013` for
  `x << (9 as u3)`, a false `E2006` for an index `const K : u32 = 5 as u2`),
  and a width constant that uses `clog2` or `~` stops `volt build` with an
  `E2005` that calls it not constant. Write the value itself.
- **`prev()` of a named constant stops `volt test` and `volt verify`**
  ([#442](https://github.com/volt-hdl/volt/issues/442)): `prev(M)` passes
  `volt check`, but the helper register is named after the constant's
  value (`past_8'd9_1`) and Verilator reports a syntax error. Write the
  constant without `prev()`: `invariant: M == 9`.
- **An array register assigned as a whole from or to a packed port**
  ([#443](https://github.com/volt-hdl/volt/issues/443)): with `r <= arr`
  or `all = r`, `volt check` and `volt build` pass, but Verilator rejects
  the generated SystemVerilog (`SEL is not an unpacked array`,
  `CASTSIZE`). Assign the elements one by one: `r[0] <= arr[0]`, …;
  `all[0] = r[0]`, …
- **A false `W3010` for two clock ports of one domain**
  ([#79](https://github.com/volt-hdl/volt/issues/79)): `in c1 : clock @c0`
  gets "reset 'rst' is shared by 2 clocks". The warning can be ignored
  there.
- **A part-select that is always out of range stops `volt test`**
  ([#124](https://github.com/volt-hdl/volt/issues/124)): `s[(p | 31) +: 20]`
  on a 20-bit `s` compiles, and Verilator stops with `SELRANGE`. Such a
  select reads nothing inside the value: remove it or write the start you
  mean.
- **Two generic modules with one name in two packages**
  ([#251](https://github.com/volt-hdl/volt/issues/251)) get a misleading
  `E1001` ("undefined name: 'M_8'") instead of `E1003`. Give one of them
  another name.
- **A chain of constants that name each other twice is slow**
  ([#390](https://github.com/volt-hdl/volt/issues/390)): with
  `const A2 : u64 = A1 + A1` and so on, the time doubles with each link,
  and `volt check`, `volt build` and the editor stop responding on a
  short file. Name the earlier constant once: `const A2 : u64 = 2 * A1`.
- **An undefined name in a large module-level `for` is slow to report**
  ([#448](https://github.com/volt-hdl/volt/issues/448)): with thousands
  of iterations, `volt check`, `volt build` and the editor take seconds to
  report the `E1001`, even on a file of a few lines. The delay goes away
  once the name is declared: fix the `E1001`.
- **A struct of your own named `Counter`**
  ([#141](https://github.com/volt-hdl/volt/issues/141)) is taken for the built-in counter: `Counter { a: x, b: true }`
  gets `E0003` ("'Counter' without its generic arguments"). Give the
  struct another name.
- **A clock alias declared below a `pipeline`**
  ([#415](https://github.com/volt-hdl/volt/issues/415)): with `type Clk = clock` written below the pipeline
  that uses it, `volt check` reports `E5011` ("a pipeline needs exactly
  one clock port (found 0)"). Declare the alias above the pipeline.

## Install

Windows (PowerShell):

```powershell
irm https://volthdl.org/install.ps1 | iex
```

Linux and macOS:

```sh
curl -fsSL https://volthdl.org/install.sh | sh
```

Running the script again updates an installed Volt to this release.
`VOLT_VERSION=0.1.5` installs this release instead of the newest one. In
a new terminal, `volt --version` prints `volt 0.1.5` followed by the
commit in parentheses. The VS Code extension is attached to this release
as `volt-hdl-0.1.5.vsix`. Verifying a download, installing by hand and
the platform notes are unchanged from 0.1.0: see
[Install Volt](https://volthdl.org/tour/install.html).

## Support

The latest release is the supported one. Fixes go into `main` and ship
with the next release. Before 1.0, a new last digit (0.1.5) brings fixes
and a new middle digit (0.2.0) may break existing code; a fix for a
silent wrong result may change the output for input that was accepted
before even in a last-digit release, as in this one. Report bugs in the
[issues](https://github.com/volt-hdl/volt/issues).

The full change log, in Turkish:
[CHANGELOG.md](https://github.com/volt-hdl/volt/blob/v0.1.5/CHANGELOG.md).
Planned work: [Roadmap](https://github.com/volt-hdl/volt/blob/main/docs/roadmap.md).
