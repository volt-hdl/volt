# Volt 0.1.0

Volt is a hardware description language with a Rust-like syntax. It
compiles to SystemVerilog and checks clock and reset domains in its type
system: a clock domain crossing without a synchronizer is a compile error.

0.1.0 is the earliest Volt release. It makes no stability promise: the
syntax, the diagnostic codes and the generated SystemVerilog may change in
0.2 and later (see [Support](#support)).

the `sync()` line from its help message fixes it

[the recording script](https://github.com/volt-hdl/volt/blob/v0.1.0/demo/cdc.tape)).

## Behavior changes

There is no earlier release to compare with. The changes below matter if
you built Volt from the `main` branch before this release: the same input
now gives a different result.

### Clock and reset domains

- A flip-flop clocked from a domain declared with `clock = none` (a domain
  with no clock edge) is now error `E3016`: in an `on` block, as a
  `sync()` destination, on the clock port of a built-in component or a
  submodule, and as the sampling clock of contracts. It used to compile to
  a `posedge` flip-flop. Combinational signals in such a domain, and
  `sync()` from it (an asynchronous input), are still accepted.
- An `on` block whose trigger is not a clock port (`on d` with
  `d : bool`), and two clock ports annotated with each other's domain,
  are now error `E3002`, reported by `volt check` and the editor as well
  as by `volt build`. SystemVerilog generation derives the clock edge and
  the reset branch of every flip-flop from the source and no longer
  assumes them.
- New warning `W3011`: a raw reset port that reaches the module's
  registers through a release synchronizer is also connected to an
  `extern` instance, which gets the unsynchronized reset. The output does
  not change.

### Registers, wires and `let`

- Writing a `wire` or an `out` port with `<=` inside an `on` block is now
  error `E0020`. It used to produce a flip-flop with an empty reset
  branch, which kept its old value through reset. The suggestion rewrites
  the signal as a register with a reset value.
- An untyped `let` takes the natural width of its expression: with `a`
  and `b` of type `u8`, `let s = a + b` is now 9 bits wide (it was 8, so
  255 + 1 gave 0). `*` doubles the width; a unary `-` turns `iN` into
  `i(N+1)`. Code that relies on wrap-around writes the type:
  `let addr : u32 = pc + 4`.
- An untyped literal `let` (`let k = 100`) now compiles, with warning
  `W2012`, as an `i32`. It used to fail with `E2005`. A literal that does
  not fit in an `i32` is `E2010`.

### Modules

- An `extern module` named like a standard library module (`EdgeDetect`,
  `SyncFifo`, `Counter`, ...), or a Volt module with such a name
  instantiated from another module, is now error `E1016`. The built-in
  module used to be taken in its place without a word. A top-level module
  with such a name (the `Counter` of the `volt new` template) stays valid.

### Commands

- `volt check` without arguments (project mode) also checks every test
  file that `volt test` finds, in subdirectories too (`build/` is
  skipped), and prints a `Checking <file>` line for each. A project that
  passed before exits with code 1 if a test file has an error.
- A test file `X_test.volt` with no sibling `X.volt` gets the full check
  in `volt check`, `volt build` and the editor, as in `volt test`: a
  missing module under test is `E8501`.
- The `Compiling` lines of `volt test` print relative paths without a
  prefix (`counter_test.volt`, `sim/deep_test.volt`; it used to print
  `.\counter_test.volt`).
- `volt --version`, `volt` without arguments, the `Version:` line of
  generated SystemVerilog and the header of SDC/XDC files name the commit
  the binary was built from: `volt 0.1.0 (abcdefg)`. A binary built
  without git, or from a release source archive, prints the version alone.
- `--color auto|always|never`, `--no-color` and `VOLT_COLOR` work with
  every command and color error and warning diagnostics. In a terminal,
  diagnostics are colored by default; they are not when the output is not
  a terminal or when `NO_COLOR` or `CI` is set. `volt check --color` used
  to fail with "unexpected argument" (exit code 2).

## Highlights

### Clock and reset domains in the type system

Every signal belongs to a clock domain. A crossing without a synchronizer
is error `E3001`, and its help message holds the line that fixes it. The
bridges are `sync()`, `sync3()` and the built-in dual-clock components
(`AsyncFifo`, `HandshakeSync`, `PulseSync`, `AsyncDualPortRam`); a
multi-bit `sync()` is warning `W3003`. For resets, Volt puts a release
synchronizer in front of a raw reset port and reports an asynchronous
reset shared by several clock domains or synchronized twice (`E3003`).
In the book:
[A clock domain crossing error](https://volt-hdl.github.io/volt/tour/cdc-error.html),
[Two clocks and CDC](https://volt-hdl.github.io/volt/tutorial/two-clocks.html),
[Reset synchronizers](https://volt-hdl.github.io/volt/cookbook/reset-sync.html).

### Contracts and formal verification

`requires`, `ensures`, `invariant` and `cover` are part of the language,
with `prev(x, N)` for the values of earlier cycles. `volt verify` writes
the model and the SymbiYosys script, runs it and maps the result back to
the line of the contract. A violated contract exits with code 6 and
leaves a counterexample VCD. In the book:
[Contracts and formal verification](https://volt-hdl.github.io/volt/tutorial/contracts-formal.html).

### Simulation, with Verilator in Docker when it is not installed

`test` blocks in `*_test.volt` files run on Verilator with `volt test`. A
failing test runs again with tracing and names its waveform file;
`volt test --watch` runs the tests again when a file is saved. When
Verilator or SymbiYosys is not installed and Docker is running,
`volt test`, `volt run` and `volt verify` run the tool in a pinned
container image (Verilator: `verilator/verilator:v5.052`) and say so in
one line. `volt doctor` shows which way each command will run. In the
book: [Tests and waveforms](https://volt-hdl.github.io/volt/tour/tests-and-waveforms.html).

### Readable SystemVerilog

`volt build` writes one SystemVerilog module per Volt module, under the
same name. Ports, registers and `let` signals keep their names, `///` doc
comments become `//` comments, registers are `always_ff` blocks with
explicit widths, and a generated synchronizer carries a comment naming
its crossing. The files need no Volt package, include or runtime:
Verilator 5.052 reports nothing on the book's example with
`--lint-only -Wall`. More outputs on request: SVA for the contracts
(`--emit=sva`), SDC/XDC constraints (`--emit=sdc,xdc`), and C and Rust
drivers for an `@mmio` register map (`--emit=rust,c`).

### Existing SystemVerilog, with `extern`

`extern module` with `@source("rtl/x.sv")` uses an existing SystemVerilog
module from Volt, with a clock domain on each port, and `volt test`
simulates the two together. In the other direction, a generated module
drops into a SystemVerilog design like any other module, with one port
you did not write: the reset `rst`. Volt does not read the SystemVerilog
file (Verilator reports a port mismatch), and an `extern` takes no
parameters and gets the raw reset (`W3011` above). In the book:
[Using Volt in an existing project](https://volt-hdl.github.io/volt/cookbook/existing-project.html),
[Wrapping SystemVerilog with extern](https://volt-hdl.github.io/volt/cookbook/extern-sv.html).

### Also in this release

- `volt new` and `volt init` project templates, `volt doctor`, and
  `volt explain <CODE>` for every diagnostic code, in English and Turkish
  (`--lang=tr`).
- A language server (`volt lsp`) and a VS Code extension, attached to
  this release as `volt-hdl-0.1.0.vsix` (it is not on the Marketplace).
- Prebuilt binaries for Windows x86_64, Linux x86_64 (static, musl) and
  macOS (Intel and Apple Silicon).

## Install

Windows (PowerShell):

```powershell
irm https://volt-hdl.github.io/volt/install.ps1 | iex
```

Linux and macOS:

```sh
curl -fsSL https://volt-hdl.github.io/volt/install.sh | sh
```

The script downloads the archive for your platform from this release,
checks it against `SHA256SUMS`, installs `volt` in your user folder (no
administrator rights) and adds it to your `PATH`. Running it again
updates Volt, `VOLT_UNINSTALL=1` removes it, and `VOLT_VERSION=0.1.0`
installs this release instead of the newest one. In a new terminal,
`volt --version` prints `volt 0.1.0` followed by the commit in
parentheses. For a computer with no development tools yet, the book
walks through it step by step:
[Setup](https://volt-hdl.github.io/volt/setup.html) and
[Install Volt](https://volt-hdl.github.io/volt/tour/install.html).

By hand: download `volt-<target>.zip` (Windows) or `.tar.gz` from the
assets below, unpack it and put `volt` on your `PATH`. To verify a
download:

```sh
sha256sum -c --ignore-missing SHA256SUMS
gh attestation verify volt-x86_64-unknown-linux-musl.tar.gz -R volt-hdl/volt
```

The binaries are not code-signed. On Windows, SmartScreen may stop a
downloaded `volt.exe` ("More info", then "Run anyway"); on macOS, a binary
unpacked from an archive downloaded in a browser needs
`xattr -d com.apple.quarantine volt`.

## Known limitations

The full list, with workarounds:
[Known limitations](https://volt-hdl.github.io/volt/limitations.html).
The main ones:

- No built-in simulator: `volt test` and `volt run` need Verilator,
  installed or in Docker.
- `volt verify` needs SymbiYosys, Yosys and an SMT solver (Linux; WSL or
  Docker on Windows). Sequential properties are limited to `prev()`: no
  sequences, no liveness.
- Reset checks cover reset release, not reset ordering.
- SystemVerilog is the output language; there is no VHDL output.
- Some constructs pass the type checker but are rejected at generation
  with `E0003`, among them arrays of structs, generic structs and enums
  with data-carrying variants.
- Volt is used by its maintainer and has no external users yet; there
  are no FPGA board or tape-out results.

## Support

- The latest release is the supported one. Fixes go into `main` and ship
  with the next release; there are no backports and no maintenance
  branches. Before reporting a bug, reproduce it on the latest release or
  on `main`: [issues](https://github.com/volt-hdl/volt/issues).
- Before 1.0, a new middle digit (0.2.0) may break existing code and a
  new last digit (0.1.1) brings fixes. A fix for a silent wrong result
  may reject input that was accepted before even in a last-digit release;
  it is then listed under Behavior changes.
- The notes of every release have a Behavior changes section. Read it
  before upgrading, and pin a version with `VOLT_VERSION` where a change
  would hurt.
